# HITL Route By Priority

## When to apply

Use this skill when an inbound HITL item arrives at the Quox inbox surface and must be dispatched to the correct org-configured inbox lane before any human-facing card is rendered. Apply it immediately after item ingestion, before any persistence or UI write. This skill is specifically designed for priority-aware routing: it reads the item's urgency tier (derived from the item body, metadata, or an upstream urgency score) and maps it to an org-configured lane such as `oncall`, `ops`, `approvals`, or `digest`. Do not use this skill to create or render the inbox card — its responsibility ends with returning the routing decision and emitting the AEE envelope. Apply whenever `item_id`, `urgency_tier`, and `org_id` are available.

## Inputs

- `item_id` (string) — Unique identifier of the inbound HITL item. Required.
- `urgency_tier` (string) — Urgency classification for the item. One of `"critical"`, `"high"`, `"normal"`, `"low"`. Required.
- `org_id` (string) — Identifier of the org whose lane configuration governs routing. Required.
- `item_type` (string, optional) — Category of the item (e.g. `"approval_request"`, `"policy_violation"`, `"anomaly_report"`). Used to resolve lane overrides when the org has per-type mappings. Default: `"general"`.
- `corr` (string, optional) — AOCL correlation id from the parent execution context. Passed through into the AEE envelope unchanged. If absent, a new `corr` is generated.
- `originating_agent` (string, optional) — Agent ID that produced the item (e.g. `"sentinel"`, `"cipher"`). Recorded in the envelope metadata and used to detect self-referral loops.
- `org_lane_config` (object, optional) — Org-level lane mapping object. If omitted, the default lane matrix is used (see Steps).

## Steps

1. Validate `urgency_tier` against the four recognised values: `critical`, `high`, `normal`, `low`. If the value is unrecognised, abort with `error: "unknown_urgency_tier"` and list valid options. Do not silently default.

2. Resolve the effective lane using the default lane matrix:

   | urgency_tier | Default lane |
   |---|---|
   | `critical` | `oncall` |
   | `high` | `ops` |
   | `normal` | `approvals` |
   | `low` | `digest` |

3. Apply org lane overrides. If `org_lane_config` contains an entry matching `{ urgency_tier }` (and optionally `{ item_type }`), replace the default lane with the org-specified lane name. Record `overridden_by_org: true` in the output when an override fires. If the override references a lane name not present in the org's registered lanes, log `lane_override_invalid: true` and fall back to the default matrix result.

4. Check for originating-agent self-referral. If `originating_agent` resolves to an agent whose primary inbox is the selected lane, reroute to `ops` and record `reason: "agent_self_referral_prevented"` in the routing note to preserve audit integrity.

5. Resolve or generate the `corr` id. If `corr` was supplied, pass it through unchanged. Otherwise generate a new ULID and record `corr_generated: true` in the output.

6. Emit the AEE envelope with the following fields: `intent: "quox.hitl.route"`, `payload: { inbox_lane: <resolved_lane>, priority: <urgency_tier>, corr: <corr>, item_id: <item_id>, originating_agent: <originating_agent | null> }`. The envelope's `corr` field at the top level must equal the resolved `corr` from Step 5.

7. Emit an AOCL trace entry recording `item_id`, `urgency_tier`, `resolved_lane`, `overridden_by_org`, and `corr` so the full routing decision is available to the audit layer.

8. Return the routing decision object (see Outputs).

## Outputs

- `resolved_lane` (string) — The org inbox lane the item must be dispatched to (e.g. `"oncall"`, `"ops"`, `"approvals"`, `"digest"`).
- `urgency_tier` (string) — The urgency tier as received and validated.
- `corr` (string) — The AOCL correlation id used in the AEE envelope.
- `corr_generated` (boolean) — `true` if a new `corr` was generated by this skill; `false` if it was inherited from the caller.
- `overridden_by_org` (boolean) — `true` if an org-level rule changed the default lane assignment.
- `lane_override_invalid` (boolean) — `true` if an org override referenced an unregistered lane and was discarded.
- `routing_note` (string) — One-sentence explanation of the lane decision, including any override, fallback, or self-referral prevention that fired. Suitable for inclusion in the rendered inbox card header.
- `aee_envelope_emitted` (boolean) — `true` when the AEE envelope was successfully written to the execution context.

## Failure modes

- **Unknown urgency tier:** Abort immediately with `error: "unknown_urgency_tier"` and return the list of valid tiers. Do not assume a default — an unrecognised tier indicates the upstream urgency classifier may have malfunctioned.
- **Lane not registered for org:** If the resolved lane (after overrides) does not appear in the org's registered lane list, fall back to `ops` as the safe default, set `lane_fallback_applied: true`, and include the original lane name in `routing_note` so the operator can correct the org configuration.
- **AEE envelope emission failure:** If the AEE envelope cannot be written (envelope bus unavailable), record `aee_envelope_emitted: false` and surface `error: "aee_envelope_emit_failed"`. The routing decision is still returned so the caller can retry envelope emission independently — do not abort the routing step.
- **org_lane_config schema invalid:** If `org_lane_config` is present but fails validation (missing keys, wrong types, or unrecognised lane values), discard it entirely, set `org_lane_config_invalid: true`, and proceed with the default matrix. Always return a routing decision.

## Notes

The four canonical urgency tiers (`critical`, `high`, `normal`, `low`) must be used consistently with their SLA windows: `critical=30min`, `high=4h`, `normal=24h`, `low=72h`. These defaults apply unless the org's SLA configuration overrides them. The `resolved_lane` value written into the AEE envelope's `payload.inbox_lane` field is what the Quox inbox surface reads to place the card in the correct column — ensure the casing matches the org's registered lane identifiers exactly, as lane matching is case-sensitive. When `originating_agent` is provided, the AOCL trace entry makes agent-originated routing fully auditable for governance reviews.
